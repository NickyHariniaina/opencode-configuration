## What I do

- Check on which branch I am
- Read these references before committing:
    - https://www.conventionalcommits.org/en/v1.0.0/#specification
    - https://github.com/conventional-changelog/commitlint/tree/master/%40commitlint/config-conventional
- Use this commit message template: `<type>(<scope>): <subject>`
- Create a commit message following the conventional commit specification and following the changes
- Commit the changes

## When to use me

Use this when either I tell you to commit the changes or you finished any change in build mode.
Ask clarifying questions about the <type> you're supposed to use.

## Examples

### Committing a change

```
feat(build): add a new feature
```

### Committing a fix

```
fix(build): fix a bug
```

### Committing a refactor

```
refactor(build): refactor a code
```

### Committing a style change

```
style(build): change the style
```

### Committing a documentation change

```
docs(build): add a documentation
```

### Committing a test change

```
test(build): add a test
```

### Committing a chore change

```
chore(build): add a chore
```
